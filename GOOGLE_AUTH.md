# Google sign-in

Web and native clients use Google only. The application sends no email, offers no password registration or reset, and does not implement its own passkeys or second factor. Account recovery, passkeys, and two-step verification are managed through Google account security.

Create a Google OAuth **Web application** client. Configure `AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET`, and a strong `AUTH_SECRET` on Next.js. For local development, put them in `nextjs/.env.local` (copy `nextjs/.env.example` as a starting point). Register the exact callback URL `https://YOUR_HOST/api/auth/callback/google`; use `http://localhost:3000/api/auth/callback/google` for local web development. Configure the OAuth consent screen and test users before publishing. Use HTTPS in deployed environments and set Auth.js `AUTH_URL` to the public host where needed behind a proxy; trust only your own ingress.

Native uses the same web OAuth client via `expo-web-browser.openAuthSessionAsync`. Set `EXPO_PUBLIC_TRPC_URL=https://YOUR_HOST/api/trpc`. The app scheme is `mernmafia`; rebuild native development/production binaries after changing this configuration. This custom-scheme flow requires a development build or installed app, not Expo Go. The browser performs the normal Auth.js Google authorization-code flow and explicitly confirms the selected account. A five-minute PostgreSQL request binds the browser cookie, native PKCE challenge, and authenticated Google user. The callback contains only a random one-time code and state; the app exchanges them with its private verifier for revocable mobile access/refresh credentials. Wrong verifiers, expired requests, replayed codes, or other browser cookies cannot complete the exchange.

Auth.js validates the Google OpenID Connect exchange (including issuer, audience, token validity, and protocol protections). The sign-in callback additionally requires Google's `email_verified` claim. Google email is retained as identity metadata; no mail is sent. Automatic account linking by matching email is disabled. Legacy password-only accounts with the same email do not automatically transfer ownership; migration needs an explicitly verified administrative process. Deploy the session-revocation migration before rollout and require existing users to sign in again.

Automated coverage checks Google-only policy, callback state matching, cancellation, PKCE exchange, expiration and replay. Google consent and OS deep links must also be tested with real Google test accounts on iOS and Android development builds before release.

References: [Auth.js Google provider](https://authjs.dev/reference/core/providers/google), [Expo WebBrowser](https://docs.expo.dev/versions/latest/sdk/webbrowser/), [Expo Crypto](https://docs.expo.dev/versions/latest/sdk/crypto/).

Local development can start without Google credentials so guest games remain available. Google sign-in is disabled until **both** `AUTH_GOOGLE_ID` and `AUTH_GOOGLE_SECRET` are nonempty in `nextjs/.env.local`. Restart the local launcher after updating them. Missing configuration returns HTTP 503 from the mobile sign-in start endpoint instead of opening an invalid Google authorization request. Production still requires both credentials.
